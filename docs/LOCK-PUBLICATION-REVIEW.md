# Native 0.6 / 41-export effect-lock publication candidate

Parent source: f8f0619b5588f2d11b44f4becd4198775d4a8bcf. Source-only review; no default promotion, consumer repin or installation is authorized by this document.

Previously ApplyHoldTimeout read plain g_lockInit while public initialization/release paths could initialize the critical section and write that flag. SetHoldTimeoutMs could create the watchdog first. Public API serialization did not protect the independent worker's read.

InitializeEffectLock now owns the only runtime initialization, through Windows INIT_ONCE. It publishes atomic readiness with release ordering after successful InitializeCriticalSectionEx; the worker checks readiness with acquire ordering before touching the critical section. Initialization failures propagate without starting a worker or entering an uninitialized lock and record the HRESULT. Public device/effect initialization paths share EnsureEffectLock. SetHoldTimeoutMs with a positive timeout ensures initialization before CreateThread, including before any device initialization. A zero/negative timeout does not create a lock or worker solely for timeout handling. FreeDirectInput and effect release keep the initialized lock for the module lifetime; INIT_ONCE is never reset during cleanup/restart.

The only destruction remains at DLL_PROCESS_DETACH after the required caller/worker quiescence. DllMain performs no wait, join, logger lock or runtime initialization. Atomic readiness does not legalize unloading with outstanding callers: stop producers, drain calls, invoke FreeDirectInput outside loader lock and the effect lock, prevent new calls and only then unload. Process teardown/explicit unload while workers remain active is outside the supported contract. OutRun's loader-lock PanicStop path remains an adoption blocker. Woden's distinct 39-export tree and the frozen OutRun/Fzero candidates are unchanged.

Tests run in fresh processes on x64 and x86. A worker-style reader first observes uninitialized readiness, then races four first initializers and 400 empty public effect release/FreeDirectInput cycles, acquiring the same published lock during the overlap. A separate --pre-init-worker process checks disabled-timeout low demand, positive pre-device worker creation with ready lock, idempotent cleanup, retained lock and restart. The existing fake active-effect stop-before-join, delayed worker acquisition of g_lock, resource-retention and concurrent-output tests remain passing. These are fake-only stress/regression checks, not a race-detector proof or real-device acceptance.

No exported name, signature, ordinal, native version, DEF or header changes. Scope stays native 0.6.0 / 41 exports. Driver Stop, logging and worker completion can still block indefinitely; no force-kill or timeout-then-free was introduced. No 46-export repair is claimed.
