# Shared digital input and binding policy

Allow a physical button or HAT direction to be assigned to several actions. Never silently remove earlier assignments or require clearing them first. Games own context dispatch: menu actions run in menus and driving actions run only in eligible gameplay. Within an eligible context, each assigned action receives a press independently once; one action must not consume another action's edge. Keep explicit global safety actions global. This change does not relax keyboard-chord or camera-default preflight rules.

The input-only candidate based on v0.12.0 extends `ReadDeviceState` without changing its existing signature: physical buttons 0..127 are unchanged; four POV hats expose eight exact directions at 128..159 (Up, Up-right, Right, Down-right, Down, Down-left, Left, Up-left). Request 160 bytes and query optional `GetInputCapabilities` bit 0. Version numbers alone are insufficient; older modules may have unrelated higher versions. Managed reads clear the output first, so old modules cannot leave stale extended bytes. A diagonal is one distinct binding, rather than an ambiguous chord of two cardinals. Neutral uses DirectInput's low-word FFFF convention; invalid angles release all directions.

Pure native fixtures test the same helper called by the actual DirectInput reader. Managed fixtures cover per-action edge delivery, held/release/disconnect and no physical-button aliasing. They open no devices and establish no hardware recognition acceptance. Consumers need the tested matched native and managed override plus their binding/capture integration. Do not replace an installed toolkit package or force-model pin merely to add POV recognition.
